# Brevora

> Read AI show notes for your YouTube subscriptions first, then decide whether to watch.

The name comes from the Latin *brevis* (brief) + *ora* (time).

**[Live demo (no login)](DEMO_URL)** · [Decision log (Chinese)](docs/decisions.md) · [Design process (Chinese)](docs/design-process/README.md) · [中文](README.md)

---

## Problem

I want to keep up with the latest international content, and ran into three problems:

- **Chinese-language coverage lags behind.** Relying on Chinese sources means always being a step behind the original.
- **Too much, too long, and English is not my first language.** I rarely finished the shows I subscribed to.
- **Other people's summaries are secondhand.** They reflect what someone else absorbed and chose to keep.

My old routine was to pick a few shows I cared about most each week, watch them if I had time, and let the rest pile up.

## What I wanted

- **Skim first, then decide.** Watch the original only when it is worth it, and filter out the rest. Notes are a filter, not a replacement for the source.
- **I choose the sources.** Notes come only from the original videos I subscribe to, with no one else's summary in between.
- **Output, not just input.** Input without output does not lead to much growth. Notes make the input wider and deeper.

## How it works

1. Sign in with Google and pin the YouTube channels you want to follow.
2. Sync the latest videos from those channels.
3. Open a video. Gemini reads the video itself and writes Traditional Chinese show notes:

   | Section | Content |
   |---------|---------|
   | One-line theme | What the video is about and its core claim |
   | Summary | 2–4 sentences on who it is for and the main conclusion |
   | Five key points | In the order they appear, each with a timestamp |
   | More highlights | Secondary points worth keeping; omitted if there are none |
   | Call to action | What you can do right after watching |

4. Click any timestamp to open the original video at that second, to verify a point or go deeper.
5. Manage videos with read status, favorites, channel filters and search.

**Why this structure?** I set the requirements and settled the format in discussion with Claude. Five points are usually enough to see the whole video; timestamps link back to the source so every point can be checked.

## Results

- I have used it for about a month, 2–3 times a week.
- I went from "watch when I have time, otherwise let it pile up" to focusing on three key takeaways a week, with my time concentrated on what I actually care about.
- I am the only user so far. No other user research has been done.

## Key decisions

Full details are in the [decision log](docs/decisions.md) (Chinese).

1. **Ship the portfolio as a frontend demo instead of using Supabase.** Free Supabase projects pause after a week without activity. The full product needs Google sign-in, and until the app passes Google's verification only listed test users can sign in, so interviewers could not get in at all. The demo uses real notes generated by the product itself, needs no login and never sleeps.
2. **YouTube blocks cloud hosts, so Gemini reads the video URL directly.** From a cloud host, YouTube returns a "Sign in to confirm you're not a bot" page, so both scraping captions and downloading audio fail.
3. **Gemini retired the old models, so model names are now configurable.** Added a fallback model and retries, and recorded the quota limits hit during testing (requests per day, tokens per minute).
4. **Known issue: summaries are stored per user.** If N users open the same video, the AI cost is N times. Planned as the next step.
5. **Fix trust-breaking bugs first.** For example, "Sync" always reported 0 new videos, and AI notes rendered without formatting.

## About the demo

- 6 videos from 3 channels (How I AI, The Diary Of A CEO, Starter Story), 352 minutes in total.
- Notes were generated by [`scripts/generate_demo_data.py`](scripts/generate_demo_data.py), which calls the product's own AI service and records the model used for each video. The notes are unedited.
- Favorites, read status and pinned channels all work, and are stored only in your browser.
- The demo does not contact YouTube, so "Sync" and generating new notes are disabled.

## Limitations and next steps

- [ ] Store summaries per video so each video is processed only once
- [ ] Security fixes: JWT passed in a URL parameter, missing OAuth `state`, secrets not checked against their defaults, raw error messages returned to the client, refreshed tokens not saved to the database
- [ ] Automated tests and CI
- [ ] Redesign the logo and visual style (the current version is temporary)

## Tech stack

| Layer | Technology |
|-------|------------|
| Frontend | React 19, TypeScript, Vite, Tailwind CSS, TanStack Query |
| Backend | FastAPI, PostgreSQL, SQLAlchemy, Alembic |
| AI | Google Gemini (`google-genai` SDK, reading YouTube URLs directly) |
| External APIs | YouTube Data API v3, Google OAuth 2.0 |
| Hosting | Demo: Vercel (frontend only) |

```
Browser ──> React frontend ──> FastAPI ──> PostgreSQL
                                 ├──> YouTube Data API (subscriptions, videos)
                                 └──> Gemini (YouTube URL → show notes)

Demo mode: React frontend ──> in-browser demo layer (pre-generated data + localStorage)
```

## Running locally

<details>
<summary>Demo mode only (no backend or API keys)</summary>

```bash
cd frontend
pnpm install
VITE_DEMO_MODE=true pnpm dev
```

Open http://localhost:5173

</details>

<details>
<summary>Full product (Google sign-in + backend)</summary>

Requires Node.js 20+, Python 3.11+, PostgreSQL, pnpm, a Google Cloud project (YouTube Data API v3 + OAuth 2.0) and a Gemini API key. See [docs/google_setup.md](docs/google_setup.md) (Chinese) for the Google setup.

1. Install the backend from the repo root (creates `backend/venv`; works on Windows, macOS and Linux):

   ```bash
   pnpm run install:backend
   cp backend/.env.example backend/.env
   ```

2. Fill in `backend/.env`:

   | Variable | Description |
   |----------|-------------|
   | `GOOGLE_API_KEY` | Gemini API key ([get one](https://aistudio.google.com/app/apikey)) |
   | `GEMINI_MODEL` | Optional. Primary model, default `gemini-3.6-flash` |
   | `GEMINI_FALLBACK_MODEL` | Optional. Used when the primary model fails, default `gemini-3.5-flash` |
   | `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` | OAuth credentials |
   | `DATABASE_URL` | PostgreSQL connection string |
   | `JWT_SECRET` | Random string (`python -c "import secrets; print(secrets.token_hex(32))"`) |
   | `ENCRYPTION_KEY` | Fernet key (`python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"`) |
   | `FRONTEND_URL` / `BACKEND_URL` | `http://localhost:5173` / `http://localhost:8000` |

3. Create the tables:

   ```bash
   cd backend
   venv/bin/alembic upgrade head   # Windows: venv\Scripts\alembic upgrade head
   ```

4. Create `frontend/.env` containing `VITE_API_URL=http://localhost:8000`.

5. Start both servers from the repo root:

   ```bash
   pnpm install
   pnpm dev
   ```

   Frontend at http://localhost:5173, backend at http://localhost:8000.

</details>

<details>
<summary>Regenerating the demo data</summary>

Requires the `GOOGLE_API_KEY` and `YOUTUBE_API_KEY` (YouTube Data API v3) environment variables.

```bash
pnpm run install:backend
backend/venv/bin/python scripts/generate_demo_data.py            # skips finished videos
backend/venv/bin/python scripts/generate_demo_data.py --only VIDEO_ID --force
```

The Gemini free tier has quota limits. If a run fails partway, run it again; only unfinished videos are processed.

</details>

<details>
<summary>Deploying the demo to Vercel</summary>

1. Import this repo in Vercel.
2. Set **Root Directory** to `frontend` (the framework is detected as Vite).
3. Add the environment variable `VITE_DEMO_MODE=true`. No API keys are needed.
4. Deploy.

</details>
